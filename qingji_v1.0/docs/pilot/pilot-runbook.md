# 青迹真实项目试用执行手册

## 目标

用 3 至 5 个不同主题、已获得授权的社会实践项目建立真实基线集 v0，记录青迹在检索、结论边界和补证决策中的实际帮助与失败类型。试用不以证明高准确率为目标。

## 项目选择

候选项目应满足：

- 有明确负责人，能够确认材料来源和授权状态。
- 至少包含两种来源角色或材料场景，便于观察证据范围和冲突。
- 材料规模适合人工复核，首轮建议每个项目 5 至 20 份文字材料。
- 不包含当前无法安全处理的高风险原文；扫描件、音频和视频暂不作为首批材料。
- 主题之间存在差异，避免所有项目使用相同词汇和材料结构。

## 执行步骤

### 准备

1. 在工作簿中登记项目、负责人内部代号、授权状态和保留期限。
2. 按数据治理流程逐份登记材料，完成本地脱敏和第二人抽查。
3. 为项目、材料、结论用例和试用会话生成稳定内部编号。
4. 将真实试用数据库、演示数据库和测试数据库放在不同目录。

### 建立人工基线

1. 每个项目选择能覆盖直接支持、部分支持、暂无支持和存在冲突的结论用例。
2. 两名标注者独立填写证据编号、关系、结果、风险标签和可接受改写。
3. 对需仲裁用例保留两份原始判断，并记录最终结果和理由。
4. 冻结基线集 v0，生成数据指纹或只读副本，后续修改必须留痕。

### 运行青迹

1. 记录人工完成同类任务的基线耗时。
2. 使用当前 `v1.4-alpha` 处理同一批材料，记录总耗时、越界提醒、采纳数、误报、漏报和困惑点。
3. 保留每条失败样例的项目编号、用例编号、系统结果、人工结果和错误分类，不在问题清单中复制敏感原文。
4. 不在试用过程中临时加入 Embedding、OCR 或新规则，以免基线失去可比性。

## 最小记录指标

| 维度 | 记录内容 |
| --- | --- |
| 时间 | 人工基线分钟、青迹流程分钟、返工分钟 |
| 检索 | 应检索证据、实际前 K 条、漏召回、误召回、零命中正确性 |
| 核验 | 人工最终四级结果、系统结果、风险标签、分歧原因 |
| 价值 | 越界提醒数、人工采纳数、补证任务完成数 |
| 使用负担 | 困惑点、重复操作、失败恢复次数 |
| 隐私 | 脱敏遗漏、云端最小发送异常、撤回与删除完成情况 |

## 停止条件

出现以下任一情况时暂停对应项目：授权或撤回状态不清，脱敏遗漏可能识别个人，材料跨项目出现，系统引用已排除证据，无法完成删除或备份恢复，或云端模型接收了超出授权范围的内容。

## 阶段交付物

- 3 至 5 个项目的试用登记与授权状态。
- 双人标注规范和已仲裁的真实基线集 v0。
- 使用耗时、采纳、误报、漏报和困惑点记录。
- 按失败类型整理的问题清单，不包含真实身份和原文。
- 是否进入混合检索或 OCR 实验的证据化决定。

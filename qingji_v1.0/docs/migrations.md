# 青迹数据库迁移与恢复

## 当前版本

数据库架构版本为 2。程序启动时先拒绝未知的更高版本，再以幂等方式创建缺失表和索引、补充旧字段，最后写入 `PRAGMA user_version` 和 `schema_migrations`。

版本 1 收口了此前的启动时升级逻辑，并明确包含：

- 项目归档字段和模型运行的结论关联字段。
- 项目专属术语表 `projects.term_pairs_json`。
- 审核人留痕 `evidence_review_events.reviewer`。
- 架构版本表 `schema_migrations`。

版本 2 新增项目级 `pilot_sessions` 表，用于保存真实试用耗时、提醒采纳、误报漏报、困惑点和后续动作。旧库升级时创建空表，不改写既有项目、材料或结论数据。

## 升级流程

1. 停止 Streamlit，避免升级过程中继续写入数据库。
2. 使用应用内项目备份导出重要项目；如需整库恢复，再额外复制整个本地数据目录。
3. 切换到目标代码版本并安装对应依赖。
4. 启动应用或运行测试。`Database.initialize()` 会完成受支持的幂等升级。
5. 核对 `PRAGMA user_version`、迁移记录、项目数量和一份项目备份恢复。

## 备份兼容策略

- 项目 ZIP 的备份格式版本与数据库架构版本分开记录。
- 当前备份格式版本为 1，新增字段和表保持向后兼容；旧版 v1 备份缺少结论候选或试用会话时按空记录恢复。
- 当前程序拒绝恢复来源架构版本高于自身支持范围的备份，避免静默丢失字段。
- 恢复时重新映射数据库编号，不覆盖已有项目，并重新校验文件哈希与实体关系。

## 回滚策略

不对数据库执行原地降级。需要回滚时，应停止应用，恢复升级前的整库副本并切回匹配的代码版本；单个项目可恢复为一个新的独立项目。任何迁移变更都必须同时提供旧库升级测试和备份往返测试。

# 青迹架构

## 当前形态

青迹是本地单机应用。Streamlit 提供交互界面，Python 工作流组织材料、证据和结论处理，SQLite 保存完整关系和历史，文件目录保存原文、脱敏文本与导出结果。

## 主要层次

| 层次 | 主要模块 | 职责 |
| --- | --- | --- |
| 交互层 | `app.py`、`pages/` | 项目、材料、审核、核验、成果、运行恢复和真实试用 |
| 工作流层 | `qingji/workflow.py` | 串联导入、生成、审核、检索、重核、补证和失败恢复 |
| 可信核验层 | `privacy.py`、`retrieval.py`、`claims.py`、`diagnostics.py` | 脱敏、候选排序、边界规则、引用校验和解释轨迹 |
| 模型适配层 | `qingji/llm.py` | 调用 OpenAI-compatible 服务并校验结构化建议 |
| 数据层 | `qingji/db.py`、SQLite、可选 FTS5 | 保存证据链实体、关系、审核事件、运行历史和试用会话 |
| 交付层 | `export.py`、`artifacts.py`、`backup.py` | 生成报告、审计文件和可校验项目备份 |
| 质量层 | `tests/`、`scripts/` | 自动化、页面、端到端、检索回归和虚构综合评测 |

## 核心数据流

1. 材料进入项目后记录来源、场景、日期、授权和模拟标识。
2. 原文在本地落盘，敏感信息被识别并生成脱敏片段。
3. 模型可基于已授权脱敏片段生成证据卡和结论候选，输出先保存为待复核状态。
4. 人工审核决定证据是否保留；每次变化追加审核事件。
5. 检索只使用当前项目中可引用的证据，项目术语映射只做受控归一化。
6. 本地规则结合证据关系给出四级结果，并保存引用、理由、风险和补证任务。
7. 证据变化触发相关结论重核，导出文件保留稳定编号和来源定位。
8. 真实试用页独立记录人工确认的耗时、提醒效果、误报漏报和后续动作，形成后续算法决策的项目内基线。

## 不变量

- 项目数据不可跨项目引用。
- 未确认授权或已排除的证据不可成为最终引用。
- 模型建议不能改变授权状态或直接决定最终四级结果。
- 审核事件只追加，不静默覆盖历史。
- 备份恢复必须校验格式、路径、哈希、关系和架构兼容性。

## 演进方向

近期保留 Streamlit 与 SQLite，先完成真实项目基线。只有真实失败样例证明有必要时，再引入混合检索、OCR、后端 API、PostgreSQL 和真实身份系统。

# 青迹 3.0 · 从实践问题到报告复核

3.0首个可运行版本以“实践问题”连接目标、行动、真实记录、阶段发现和报告。代码基于2.0复制后独立开发，相邻`str`（1.0）和`qingji_v2.0`保持原样。

## 使用流程

1. 首页选择“开始一项实践”，填写主题、希望了解的事情和1至8个开放问题。对象、地点、时间和团队条件可以稍后补充；也可以从实践中或整理阶段进入。
2. 生成少量下一步行动。默认使用已配置 AI，发送目标、问题、行动和纳入的关联记录；不再逐次勾选。生成失败不会改为模板冒充AI成功。
3. 修改建议并确认加入行动安排，然后沿用已有成员、日期、分工和讨论功能。采纳建议不代表执行完成。
4. “记下实际发现”保存原始记录、来源、时间、场景、阶段发现和未弄清楚的问题。记录进入实践材料，默认纳入 AI 分析；是否完成行动由团队另行确认。
5. 更新建议时读取当前进展。目标、行动完成状态、原文、来源或纳入范围变化会使旧建议失效；先前建议保留历史。重复采纳不重复创建任务。
6. 将纳入的记录整理为带问题和来源的报告初稿，结论部分保留待团队撰写。已有报告不被覆盖；随后进入原有报告复核、修改、补证、导出。

仍可展开“已有报告，直接开始复核”，直接使用报告功能。界面保留实践项目、实践材料、结论核验三个入口和白紫层次，正文16px。

## 本地运行

Python 3.10+及Node环境。Python依赖见`requirements.txt`，前端安装锁定依赖后构建：

```powershell
python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
python -B server.py --port 8770
```

也可双击`启动青迹3.0.cmd`。本地网址为`http://127.0.0.1:8770`，与2.0的8766分开。程序只监听本机，数据在本目录`data/projects.sqlite3`，不会自动读取旧版本数据库。

模型连接使用`QINGJI_V3_API_BASE`、`QINGJI_V3_MODEL`、`QINGJI_V3_API_KEY`，或本目录忽略提交的`data/ai-config.json`。不自动加载旧`.env`。本机经用户授权复用的连接信息没有随仓库上传。

## 版本与交接

可导入2.0的1版项目包；无阶段分析历史时仍导出2版项目包；包含阶段分析历史时导出3版包，保留实践问题、行动关系、观察记录、指导输入快照及分析历史。当前支持导入1、2、3版包。导入创建独立副本，底层保留材料处理标记，界面默认启用 AI，仍可排除材料，导入指导不能直接采纳，报告历史仍需本机复核。2.0不能导入3.0新包，不能把新包降级后丢失关系。

## 当前边界

- 首版优先支持访谈、观察、公开资料整理型社会实践；资料方向是检索建议，没有执行联网搜索。
- 前期指导与报告支持判断独立。团队阶段发现仍需核对，任务完成不证明成效。AI结构和引用校验不证明语义准确。
- 项目可保存100份材料、总计480,000字，单份仍最多48,000字；报告24,000字。单轮AI最多8份材料、合计48,000字，保存容量与本轮纳入分开；超限明确拒绝，不截断。目标800字/项、8个问题、30次指导历史；当前适合小规模首版验证。
- 基础Word导出不保留上传稿排版；扫描PDF不做OCR。团队成员与署名是本机分工，尚无账号系统和跨设备实时协同。
- 未实现自动代写结论、自动联系对象、自主网络采集或长期实践效果评估。

## 默认 AI 与首次核验

实践指导、报告复核和追问默认调用已配置 AI，点击相应操作后发起请求；保存材料本身不会自动发起付费请求。材料仍可从处理范围中排除。模型失败不标记审核完成，也不会用模板伪装成功。

没有核验历史也可以进入结论核验：上传报告、粘贴正文，或将已保存材料用作待核验报告。选择已有材料后保留原记录，并从证据范围中排除它，避免报告为自身作证。非标准问题类别归入“其他”并提示；原句定位、引用和支持关系继续严格校验。

经过明确授权的真实模型测试使用隔离数据库和虚构材料；它验证连接与完整流程，不代表准确率评估。

## 2026-10-21 实践记录衔接

在“行动与记录 → 实际发现了什么”中，使用“关联已有材料”将已上传或快速保存的材料接到实践问题，也可选择该问题下的行动。不复制原文、不自动完成行动；排除材料仍不参与 AI 指导和报告初稿。同一材料可以关联不同问题，同一问题下重复关联会被拒绝。

展开阶段记录，点击“编辑阶段记录”，可修改问题、行动、团队发现和未解问题，并对照当前原文。来源变化时，普通保存保留待核对提示；只有“保存并确认已核对原文”才更新来源核对状态，这不等于结论获得 AI 支持。材料移除后保留备注，但不能确认不存在的原文，也不会将其用于指导或报告初稿。已有报告仍由作者编辑，不会因阶段发现更新而被覆盖。

本轮验证：后端 241 项、前端 51 项、Sites 4 项通过，生产构建通过；隔离 Edge 浏览器验证关联、编辑、草稿保护、来源核对和报告衔接，390/768/1440 宽度无横向溢出。本轮没有调用真实模型，新增操作不需要模型调用。

## 2026-10-22 手动行动与实践问题

“行动与记录 → 新建实践任务”现在可选择关联问题，也可暂不关联。已有实践任务可在“分工与讨论”调整问题；卡片显示对应问题和阶段记录数量。关联后的手动任务会进入该问题的行动统计、指导上下文和记录表单，保存记录不会自动完成行动。

已有阶段记录的行动不允许直接换问题或取消关联。若确需调整，请先编辑对应阶段记录，解除或调整“对应行动”，再修改任务；原记录的问题、发现和来源保持不变。补证任务仍围绕原报告结论，不转换为实践问题任务。

验证：249 项后端测试经全量与针对性复测通过，51 项前端和 4 项 Sites 检查通过；构建、Edge 完整流程及 390/768/1440 宽度检查通过。本轮隔离验证无真实模型或外部 HTTP 调用。

## 从行动直接记录发现

已关联实践问题的任务卡提供“记下这项行动的发现”，点击后展开实际记录表单，自动选中问题和行动并定位正文。再次点击同一行动会保留草稿；改记另一项行动前会提示是否放弃未保存内容。保存后清空该条输入，原始记录进入材料，行动仍由作者另行确认完成。未关联问题的任务需先在“分工与讨论”建立关联。

## 阶段记录查找与来源回看

有阶段记录的实践任务卡提供“查看这项行动的记录”，自动展开并筛选该行动。记录列表可按问题、行动（含未关联行动）和关键词联合筛选，关键词覆盖团队发现、未解问题、当前原文与材料名称。清除筛选恢复全部记录。

每条记录可展开当前保存的原文、来源类型、采集时间和场景。同名材料按 ID 定位；来源变化仍提示待核对；排除材料可本机回看但不因此恢复 AI 纳入；来源被移除时只保留备注，不还原或编造原文。筛选和回看不写项目，不清除正在编辑的记录草稿。

### 持续整理实践报告

行动与记录中可查看、下载最新实践整理稿，即使已有报告也能继续整理。整理稿按问题汇集已保存且纳入的关联材料、阶段发现与未解问题；来源变更会提示重新核对。预览和下载不覆盖正文或复核结果，未保存实践草稿需先保存。首次整理为报告初稿的入口仍保留。

### 报告续写与草稿保护

项目概览中的“编辑报告正文或补充结论”接续当前正文，包括复核中已采纳的改写或手动修订。切换项目内分区保留输入；离开或刷新时提醒未保存内容。未保存时阻止更换报告与启动核对，保存失败保留输入。保存后标记待复核，历史核对记录保留；可确认放弃本次修改。此处草稿自动备份到当前浏览器；仍需主动保存到项目。

### 交付前回看阶段记录

交付前检查新增“需要核对来源的阶段记录”，列出来源原文或场景等发生变化、关联材料已移除的记录；下载摘要同步保留提醒。点击“去查看”进入行动与记录并展开阶段记录，项目内跳转保留未保存的报告输入。单纯排除材料不会产生来源变化提醒；确认已核对当前原文后，对应变化提示消失，但不改变 AI 支持状态或自动恢复纳入。

### 从交付提醒定位阶段记录

每条阶段记录来源提醒提供“查看这条记录”，按记录标识定位，自动展开可用原文并聚焦记录。清除筛选恢复全部记录；切换问题、行动或搜索词也会退出单条定位。已移除来源不还原原文，过期检查需更新后才能逐条跳转。

### 按来源状态整理阶段记录

阶段记录可筛选“来源待核对、来源已修改、来源已移除、材料已排除”，并与问题、行动、关键词组合。来源待核对包含变化和缺失；排除不等于来源异常，已排除的材料仍可能需要核对来源。清除筛选恢复全部；任务入口和交付检查单条入口重置旧状态筛选。筛选不保存项目、不改变纳入范围，也不清除正在编辑的记录。

### 材料保存容量与本轮 AI 范围分离

项目可以持续积累材料，包括第9条及以后的现场记录。材料页显示已保存份数、本轮纳入份数与字数，可按实践问题仅纳入关联材料，也可清空本轮范围而保留所有材料。选择替换本轮纳入范围，保存后生效，不自动调用 AI。

新增材料仍默认纳入；超过单轮限额时允许保存，但必须调整范围后才能处理。报告复核/追问按本轮纳入处理，实践指导仅使用其中已关联问题的记录，仍受输入长度检查约束。系统不自动截断、不自动排除、不宣称读取了未纳入材料。当前尚无自动检索、分批汇总或独立的多套范围方案。

项目包保留全部已保存材料和实践关系；既有12MB项目包限制不变，大量历史快照仍可能达到该限制。旧客户端可能不接受扩大后的项目，接收方应更新到本版。单份材料和报告限额未放宽。

### 主要输入的浏览器草稿备份

报告续写、复核正文编辑、首次粘贴正文、实践方向、现场记录、阶段发现/材料关联、快速记录/材料文字编辑使用统一草稿备份。输入后显示备份状态，刷新或关闭浏览器后，在同一浏览器、同一地址重新打开项目并进入对应表单，可明确恢复或删除备份。旧会话中的报告编辑草稿仍可通过原恢复入口读取。

备份按项目和表单分开，多窗口各有副本；恢复不会写回项目或调用 AI。版本变化会提示核对，报告更换后旧复核草稿可恢复到续写框。保存成功只清理本次草稿及所恢复且未再次修改的副本；保存失败保留。浏览器无法存储时明确提示，仍可主动保存项目。

备份属于当前浏览器的 localStorage，未加密，不进入项目包；清除网站数据、无痕窗口退出、换设备或换访问地址可能无法恢复。请勿将浏览器草稿视为正式项目备份。当前不覆盖任务备注、讨论消息和所有未采纳的 AI 建议；本机项目备份可在项目内单独保存，跨设备使用下载的项目包导入；定时自动备份仍待实现。

### 项目备份与恢复

项目内展开“项目备份与恢复”，可保存当前已提交版本、查看历史列表、下载项目包、恢复为独立副本或删除指定备份。每个项目最多 20 份，项目包内容完全相同时重复保存不会占用新名额；新增或删除阶段分析后，即使正文版本未变也可保存新备份；达到上限时明确拒绝，不自动淘汰旧备份。未保存的实践输入需先提交，过期窗口不能将新版本误标为当前版本。

本机备份保存在与工作库同目录的独立 `projects-backups.sqlite3`，不修改当前项目版本。恢复复用项目包完整性与关系校验，不覆盖原项目；历史判断标为未在本机复核，材料授权需重新检查，恢复不调用模型。备份保存文字、来源、问题、行动、记录关联及核验历史，不含原上传文件二进制、浏览器草稿或服务配置。沿用项目包最多 12 MB、100 次核验历史的边界，超限拒绝且保留原内容。

这是主动保存的本机快照，不是定时或异地备份。同设备故障仍可能同时丢失工作库与备份库，建议定期下载到其他位置；已下载的包可从首页“导入项目”恢复。如果工作库文件丢失但独立备份库仍在，可在首页“本机备份库”找到并恢复副本；工作库损坏时可先下载备份留存，此入口不会覆盖或自动修复损坏库。

验证：263 项后端、56 项前端、4 项 Sites 检查及生产构建通过；隔离 Edge 验证保存失败重试、下载、恢复不覆盖、版本保护、删除、草稿保护以及 390/768/1440 宽度。无真实模型调用。

### 沿着实践问题推进

在项目概览的“沿着问题推进”中选择一个实践问题，可查看它关联的行动、阶段发现与原始来源入口，以及团队记录的待了解情况。列表不推断问题已经解决：行动完成不代表结论成立，未填写疑问也不代表没有不确定性。来源已修改、移除或排除时保留提示；状态读取失败明确显示。

可直接为当前问题记录现场情况，或为某项关联行动记记录；进入表单时预选对应关系，原有草稿保护继续生效。查看问题全部记录会预选问题筛选，查看某条记录会展开其当前原始来源。未关联具体行动的记录仍可属于问题。

每个问题可独立预览和下载整理稿，只包含该问题已保存且纳入、已确认处理授权的关联材料；保留来源、阶段发现、待了解情况和来源变化提醒。切换问题或项目版本会清空旧预览；未保存输入时禁止整理，旧窗口请求返回冲突。单问题整理不自动写报告，完整项目整理入口仍保留。这是基于记录的确定性整理，尚非 AI 综合分析或自动生成可靠结论。

验证：266 项后端、56 项前端、4 项 Sites 检查及构建通过；Edge 新问题工作区与原行动记录流程均通过，390/768/1440 宽度无横向溢出；模型与外部 HTTP 尝试均为 0。

### 按问题进行 AI 阶段分析

问题工作区中点击“用 AI 整理阶段发现”，会按当前实践问题整理已有记录、不同反馈与待了解事项。仅发送该问题的目标、已纳入且确认处理授权的关联材料、团队发现及疑问，不发送其他问题材料、报告或团队讨论。沿用单轮最多 8 份 / 48,000 字材料限制，序列化上下文最多 60,000 字，超限拒绝且不截断。

每条候选理解必须带记录标识、材料标识及对应原文引文；不同反馈条目需至少两份不同材料。服务端验证引文确实属于本轮来源，不能据此认证语义或事实。缺少来源、伪造引文、格式错误和模型失败均明确报错，不回退为伪装的 AI 结果。来源修改会提示阶段发现需重新核对；分析前后均检查项目版本，切换问题后丢弃迟到结果。

点击引文可回到原始记录，下载候选会保留引用和限制。成功结果及当时来源快照保存在本机分析历史中，可进入项目包和备份，但不自动写入报告、实践记录或任务；未保存输入先提交再分析。本功能不是最终结论审批，也不自动认定问题解决。

验证：272 项后端、56 项前端、4 项打包检查及构建通过；Edge 成功展示使用受控响应，另验证真实服务拒绝模型时明确失败、来源跳转、下载、迟到响应隔离及三种屏宽。单独使用两份虚构记录完成 1 次真实模型连通测试，格式及引文校验通过，未修改项目。连通结果不是准确率评估。

### 将分析候选带入报告草稿

每条 AI 阶段分析旁可点击“带入报告草稿”。系统先核对服务器项目版本，再把该条候选、问题、原文引文、材料/记录标识和分析限制追加到当前报告编辑框，保留原正文与已采纳改写，并标明“待核对的 AI 候选”。此操作不保存项目，也不表示结论已经成立。

已有未保存输入时先保存或放弃；跨窗口版本变化、正文变化或追加后超过编辑框 24,000 字符上限时拒绝，不覆盖、不截断。带入后使用既有浏览器草稿备份与明确恢复机制；作者可修改或放弃，主动保存后进入待复查状态。引用在草稿中是可读文字，尚非结构化报告引用对象。

验证：59 项前端、4 项打包检查和构建通过；隔离 Edge 验证保留正文、不自动写项目、草稿恢复、保存失败重试、成功待复查、跨窗口版本拒绝、超限保护及 390/768/1440 布局。分析返回使用受控模拟，本轮没有调用真实模型，无后端变更。

### 将待了解事项接到后续行动

问题工作区的团队疑问可点击“为这条疑问安排行动”，AI 阶段分析中的待了解事项可点击“据此起草后续行动”。两种入口都会先打开编辑表单，确认行动内容、负责人、截止日期和补充说明后才保存。保存为待执行实践任务，关联原问题，在备注中保留疑问与材料/记录标识；不会完成任务、生成证据或消除原疑问。

行动草稿接入浏览器备份与明确恢复。保存失败保留输入；来源版本变化时拒绝旧草稿，需重新核对后起草；来源被移除或 AI 引文不匹配时拒绝。相同问题下、仍保留相同来源备注的既有行动会阻止重复添加；若人为改写或删除来源备注，该判重不再可靠。来源关联以备注保留，不新增独立来源实体。

任务保存后，可从相关行动进入实际记录，预选问题和行动；项目包与备份沿用现有任务、备注、问题关联结构。来源已关联不代表任务已经取得新材料。

本轮全量回归：276 项后端测试、59 项前端测试、4 项打包检查和构建均通过。

### 阶段分析历史与来源快照

成功的 AI 阶段分析自动保存为本机历史，重新打开项目可查看最近一轮；可切换旧轮次、展开分析时的来源快照、下载或删除指定历史。每项目最多 20 次，达到上限会在调用模型前提示整理历史，不自动淘汰。删除历史不修改已保存的报告或行动，既有备份中的副本也会保留。

历史同时保存问题、目标及已脱敏的本轮关联记录快照。当前输入指纹不同或分析来自导入包时，仍可回看和下载，但不能直接带入报告或起草行动，需重新生成。与该问题输入无关的项目修改不使分析失效。保存分析历史不改变正文版本；保存时仍在事务中检查项目版本，拒绝并发修改后的过期结果。

包含分析历史的项目包升级为3版，保留结果、原文快照及原始来源版本；导入后始终标为外部历史未复核。旧客户端不能读取3版包，接收方需要升级。无分析历史继续导出2版包，保留1/2版导入兼容。完整包12MB限制不变，超过明确拒绝。

历史功能验证：283 项后端、59 项前端、4 项打包检查、构建及隔离 Edge 八组流程通过，无真实模型调用。

### 首页本机备份库

首页“本机备份库”统一展示所有主动保存过的备份，支持按备份时的项目名称搜索、每页20份分页、下载和精确删除。列表只读取备份元信息，不展开材料正文。即使原项目已不在工作库中，备份仍可查找。

点击“预览备份内容”会先复用导入时的结构和完整性校验，再显示报告名称与长度、材料/行动/阶段记录/复核/分析历史数量及实践问题。若原项目仍在，可对照当前名称、版本和材料数量；预览不会修改项目。确认后恢复为独立副本，保留其他项目与备份，历史仍需复查。损坏备份不显示可用恢复按钮；当前工作库不可读时先下载留存，不执行覆盖修复。

验证：288 项后端检查经全量与定向复测通过，59 项前端、4 项打包检查、构建和 Edge 九组流程通过；包括原项目移除后恢复、下载、损坏拒绝、错误重试和三种屏宽。均为隔离虚构数据，无真实模型调用。

### 阶段分析质量评估与人工复核

固定六类虚构案例覆盖小样本外推、转述与亲历、不同条件的反馈、来源修改、材料内诱导指令和处理范围隔离。评估直接调用当前阶段分析实现，不读取、创建或修改项目数据库。案例、输入和实现保存指纹，结果目录每次独立创建，保留失败与短的无效输出；不记录配置密钥、服务地址或异常原文。

在 `qingji_v3.0` 目录运行：

```powershell
python -B scripts/evaluate_synthesis.py
python -B scripts/evaluate_synthesis.py --live
python -B scripts/evaluate_synthesis.py --compare output/evaluations/某次运行/results.json output/evaluations/另一次运行/results.json
```

默认是受控回放，不调用模型，也不是模型能力测评。`--live` 使用3.0自己的配置，每例至多一次调用，共六例，不自动重试。输出位于忽略目录 `output/evaluations/`，包含完整结果和可离线打开的 `review.html`。失败案例保留，整轮存在失败时返回非零退出码。运行被中断时尚未完成的整轮不会保存，不能据此推断通过。

复核页同时保留检查要点、来源和候选表述，允许选择“符合、存在问题、无法判断”，并填写依据后下载复核记录；所有条目初始为待复核。判断仅暂存当前页面，不自动写入项目或浏览器存储，关闭前需确认下载完成。下载记录关联运行和模型输出指纹，未完成项不会自动算作通过。比较命令只接受未修改、同方式、同案例和同输入的结果，显示结构校验及输出变化，不推算语义提升。

自动校验只能确认结构与引文存在；有真实引文的错误外推仍可能通过。案例中明确测试这一边界，不把结构通过率当作准确率。真实模型结果需要作者或独立复核者判断；当前六例也不代表真实团队试用、广泛鲁棒性或统计准确率。配置可能变化、服务端模型更新也可能导致不同输出，本工具不是确定性复现真实模型的保证。

基于本轮评估发现，阶段分析提示补充了来源判断约束：仅凭“回访、访谈、记录”标题不能把内容定性为转述或亲历，原文未明时保留未知。

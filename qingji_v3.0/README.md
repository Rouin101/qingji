# 青迹 3.0 · 从实践问题到报告复核

3.0首个可运行版本以“实践问题”连接目标、行动、真实记录、阶段发现和报告。代码基于2.0复制后独立开发，相邻`str`（1.0）和`qingji_v2.0`保持原样。

## 使用流程

1. 首页选择“开始一项实践”，填写主题、希望了解的事情和1至8个开放问题。对象、地点、时间和团队条件可以稍后补充；也可以从实践中或整理阶段进入。
2. 生成少量下一步行动。默认使用已配置 AI，发送目标、问题、行动和纳入的关联记录；不再逐次勾选。生成失败不会改为模板冒充AI成功。
3. 修改建议并确认加入行动安排，然后沿用已有成员、日期、分工和讨论功能。采纳建议不代表执行完成。
4. “记下实际发现”保存原始记录、来源、时间、场景、阶段发现和未弄清楚的问题。记录进入实践材料，默认纳入 AI 分析；是否完成行动由团队另行确认。
5. 更新建议时读取当前进展。目标、行动完成状态、原文、来源或纳入范围变化会使旧建议失效；先前建议保留历史。重复采纳不重复创建任务。
6. 将纳入的记录整理为带问题和来源的报告初稿，结论部分保留待团队撰写。已有报告不被覆盖；随后进入原有报告复核、修改、补证、导出。

仍可展开“已有报告，直接开始复核”，直接使用报告功能。界面保留实践项目、实践材料、结论核验三个入口和白紫层次，正文16px。

## 本地运行

Python 3.10+及Node环境。Python依赖见`requirements.txt`，前端安装锁定依赖后构建：

```powershell
python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
python -B server.py --port 8770
```

也可双击`启动青迹3.0.cmd`。本地网址为`http://127.0.0.1:8770`，与2.0的8766分开。程序只监听本机，数据在本目录`data/projects.sqlite3`，不会自动读取旧版本数据库。

模型连接使用`QINGJI_V3_API_BASE`、`QINGJI_V3_MODEL`、`QINGJI_V3_API_KEY`，或本目录忽略提交的`data/ai-config.json`。不自动加载旧`.env`。本机经用户授权复用的连接信息没有随仓库上传。

## 版本与交接

可导入2.0的1版项目包；3.0导出2版项目包，保留实践问题、行动关系、观察记录、指导输入快照及历史。导入创建独立副本，底层保留材料处理标记，界面默认启用 AI，仍可排除材料，导入指导不能直接采纳，报告历史仍需本机复核。2.0不能导入3.0新包，不能把新包降级后丢失关系。

## 当前边界

- 首版优先支持访谈、观察、公开资料整理型社会实践；资料方向是检索建议，没有执行联网搜索。
- 前期指导与报告支持判断独立。团队阶段发现仍需核对，任务完成不证明成效。AI结构和引用校验不证明语义准确。
- 材料沿用2.0限额：8份、总计48,000字；报告24,000字。记录达到材料限额后会明确拒绝，不截断。目标800字/项、8个问题、30次指导历史；当前适合小规模首版验证。
- 基础Word导出不保留上传稿排版；扫描PDF不做OCR。团队成员与署名是本机分工，尚无账号系统和跨设备实时协同。
- 未实现自动代写结论、自动联系对象、自主网络采集或长期实践效果评估。

## 默认 AI 与首次核验

实践指导、报告复核和追问默认调用已配置 AI，点击相应操作后发起请求；保存材料本身不会自动发起付费请求。材料仍可从处理范围中排除。模型失败不标记审核完成，也不会用模板伪装成功。

没有核验历史也可以进入结论核验：上传报告、粘贴正文，或将已保存材料用作待核验报告。选择已有材料后保留原记录，并从证据范围中排除它，避免报告为自身作证。非标准问题类别归入“其他”并提示；原句定位、引用和支持关系继续严格校验。

经过明确授权的真实模型测试使用隔离数据库和虚构材料；它验证连接与完整流程，不代表准确率评估。

## 2026-10-21 实践记录衔接

在“行动与记录 → 实际发现了什么”中，使用“关联已有材料”将已上传或快速保存的材料接到实践问题，也可选择该问题下的行动。不复制原文、不自动完成行动；排除材料仍不参与 AI 指导和报告初稿。同一材料可以关联不同问题，同一问题下重复关联会被拒绝。

展开阶段记录，点击“编辑阶段记录”，可修改问题、行动、团队发现和未解问题，并对照当前原文。来源变化时，普通保存保留待核对提示；只有“保存并确认已核对原文”才更新来源核对状态，这不等于结论获得 AI 支持。材料移除后保留备注，但不能确认不存在的原文，也不会将其用于指导或报告初稿。已有报告仍由作者编辑，不会因阶段发现更新而被覆盖。

本轮验证：后端 241 项、前端 51 项、Sites 4 项通过，生产构建通过；隔离 Edge 浏览器验证关联、编辑、草稿保护、来源核对和报告衔接，390/768/1440 宽度无横向溢出。本轮没有调用真实模型，新增操作不需要模型调用。

## 2026-10-22 手动行动与实践问题

“行动与记录 → 新建实践任务”现在可选择关联问题，也可暂不关联。已有实践任务可在“分工与讨论”调整问题；卡片显示对应问题和阶段记录数量。关联后的手动任务会进入该问题的行动统计、指导上下文和记录表单，保存记录不会自动完成行动。

已有阶段记录的行动不允许直接换问题或取消关联。若确需调整，请先编辑对应阶段记录，解除或调整“对应行动”，再修改任务；原记录的问题、发现和来源保持不变。补证任务仍围绕原报告结论，不转换为实践问题任务。

验证：249 项后端测试经全量与针对性复测通过，51 项前端和 4 项 Sites 检查通过；构建、Edge 完整流程及 390/768/1440 宽度检查通过。本轮隔离验证无真实模型或外部 HTTP 调用。

## 从行动直接记录发现

已关联实践问题的任务卡提供“记下这项行动的发现”，点击后展开实际记录表单，自动选中问题和行动并定位正文。再次点击同一行动会保留草稿；改记另一项行动前会提示是否放弃未保存内容。保存后清空该条输入，原始记录进入材料，行动仍由作者另行确认完成。未关联问题的任务需先在“分工与讨论”建立关联。

## 阶段记录查找与来源回看

有阶段记录的实践任务卡提供“查看这项行动的记录”，自动展开并筛选该行动。记录列表可按问题、行动（含未关联行动）和关键词联合筛选，关键词覆盖团队发现、未解问题、当前原文与材料名称。清除筛选恢复全部记录。

每条记录可展开当前保存的原文、来源类型、采集时间和场景。同名材料按 ID 定位；来源变化仍提示待核对；排除材料可本机回看但不因此恢复 AI 纳入；来源被移除时只保留备注，不还原或编造原文。筛选和回看不写项目，不清除正在编辑的记录草稿。

### 持续整理实践报告

行动与记录中可查看、下载最新实践整理稿，即使已有报告也能继续整理。整理稿按问题汇集已保存且纳入的关联材料、阶段发现与未解问题；来源变更会提示重新核对。预览和下载不覆盖正文或复核结果，未保存实践草稿需先保存。首次整理为报告初稿的入口仍保留。

### 报告续写与草稿保护

项目概览中的“编辑报告正文或补充结论”接续当前正文，包括复核中已采纳的改写或手动修订。切换项目内分区保留输入；离开或刷新时提醒未保存内容。未保存时阻止更换报告与启动核对，保存失败保留输入。保存后标记待复核，历史核对记录保留；可确认放弃本次修改。此处草稿尚未自动备份，需主动保存。

### 交付前回看阶段记录

交付前检查新增“需要核对来源的阶段记录”，列出来源原文或场景等发生变化、关联材料已移除的记录；下载摘要同步保留提醒。点击“去查看”进入行动与记录并展开阶段记录，项目内跳转保留未保存的报告输入。单纯排除材料不会产生来源变化提醒；确认已核对当前原文后，对应变化提示消失，但不改变 AI 支持状态或自动恢复纳入。

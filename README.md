# 青迹

**青迹——面向高校社会实践的可信证据链智能体**

青迹不替社会实践团队编造或“润色”事实。它把已授权材料整理为可追溯的证据卡，检查一句待写入报告的结论是否超出当前证据，并将未解决的问题转化为补证任务。

> 当前仓库内置“数字便民服务体验调研”项目，用于展示完整的材料、证据、结论和成果闭环。

## 项目状态（v1.2 功能增强版）

文字版可信证据链闭环已在本机离线跑通：

- 存储、脱敏、证据抽取、本地检索、结论规则、项目数据、Markdown 导出与工作流模块均已就绪。
- 支持创建和切换多个项目，各项目的材料、证据、结论和补证任务相互隔离。
- 支持项目重命名、归档、恢复和安全删除；内置项目作为基础工作区保留。
- 支持把单个项目完整导出为带版本、大小和 SHA-256 哈希清单的 ZIP 备份包，再以新项目名称安全恢复；材料、证据、审核历史、结论、任务、评测记录及青迹托管的原文/脱敏文件会一起迁移。
- 支持按四级核验状态和关键词筛选历史结论、切换查看任意记录，并在项目概览查看结论状态分布。
- 每次核验会保存可解释检索诊断，包括候选排名、相关分、命中依据、阈值判断，以及因授权或审核状态被排除的材料。
- 证据批准、撤回或编辑后，会自动重新核验当前项目的全部结论，并同步关闭或重开系统生成的补证任务，避免旧判断继续引用已撤回证据。
- 每次人工批准、编辑或撤回证据都会追加保存修改前后状态、变更字段、时间和触发重核的结论；审核说明可选填，审核历史不可通过公共接口修改或删除，并随可信导出一同保留。
- 证据审核说明现在可以留空；审核页默认折叠证据卡、打开待审核卡时默认选中“已批准”，并支持在确认授权范围后批量批准待审核卡片。配置 DeepSeek 后，还可以明确确认信任模型并批量写入模型返回的批准/拒绝状态，未确认授权的卡片不会发送给模型。
- 长材料仍会保留细粒度片段用于追溯和检索，但相邻片段会合并为审核卡，每份材料默认最多生成 40 张卡，避免一次出现几百张重复审核项。
- 导入材料时会优先从正文和文件名本地识别来源角色、采集场景和采集日期；识别不到的字段会明确提示手动填写，识别结果仍需提交前核对。
- 已确认授权的非空材料如果遇到异常分段，系统会使用脱敏全文生成一张兜底审核卡，不再静默完成为 0 张卡片。
- 结论页在明确确认后可让模型复核候选证据与结论的实际关系，将仅有词面命中的卡片降为背景；模型不改变本地四级判定、授权边界或引用编号校验。批量证据审核按批次请求模型，并在整批完成后统一重新核验结论，减少网络往返和重复计算。

- 项目概览、侧栏和三个工作页面会根据当前材料、证据、结论与补证任务状态，统一给出一个可直接进入的下一步动作，减少在页面和标签之间来回寻找。
- 存储层禁止通过更新接口把材料、证据、结论、任务或运行记录重挂到其他项目；跨项目目标证据、完成材料和结论运行记录都会被拒绝。

## 当前可体验的闭环

1. 创建或切换社会实践项目。
2. 导入文字材料，如实填写来源角色、采集场景与授权状态。
3. 在本地识别手机号、身份证号、邮箱以及用户指定的敏感词。
4. 查看脱敏后的证据卡，并人工批准或拒绝；证据状态或内容改变时，已有结论会自动按最新证据集重新核验。
5. 输入一句准备写进报告的结论，获得“已有支持、部分支持、暂无支持、存在冲突”四级结果。
6. 查看关联证据、稳妥改写与补证任务；加入新的经授权材料后重新核验。
7. 导出带证据编号、来源目录和未解决缺口的 Markdown。
8. 在“项目概览”生成完整 ZIP 备份包，并校验后恢复为新的独立项目。

## 使用指引（第一次使用）

### A. 先查看当前项目

推荐第一次使用时先查看当前项目，熟悉完整闭环：

1. 打开“项目概览”，确认当前项目为“数字便民服务体验调研”。
2. 进入“材料与证据”，在“审核证据卡”查看已有证据；也可以在“导入文字材料”中添加新的项目材料。
3. 进入“结论核验”，直接使用示例结论“当地居民普遍认为线上办事平台使用困难。”，点击“开始核验”。
4. 查看四级结果、关联证据、规则提醒、稳妥改写和补证任务。
5. 点击“加入不同观点材料”，再点“重新核验”，观察结论如何变为冲突状态。
6. 进入“成果与缺口”，查看结论—证据对应表，并在“可信导出”下载 Markdown。

页面顶部的 1—4 步导航会标出当前位置和推荐的下一步；页面中的“材料已保存”不等于“可以引用”，必须同时满足“已确认授权”和“已批准”。

### B. 建立新项目

1. 在“项目概览 → 新建项目”填写项目名称和说明。
2. 在“材料与证据 → 导入文字材料”粘贴文字或上传 `.txt`/`.md`/`.docx`/`.pdf` 文件；已有多个同场景文件时，可展开“批量导入文字文件”。Word 文件需为未加密的 `.docx`，PDF 需包含可提取文本。
3. 如实填写来源角色、采集日期、采集场景和授权状态；批量导入会将同一组元数据应用到所选文件。
4. 勾选确认后点击“本地检查并生成证据卡”或“批量本地检查并生成证据卡”。隐私识别和脱敏在本地完成。
5. 切换到“审核证据卡”，逐张检查标题、摘要、证据类型和原文定位；需要引用时将审核结论设为“已批准”。审核说明可以留空；也可以在“批量审核工具”中明确确认后，一键批准全部已授权待审核卡片。
   若已配置 DeepSeek，还可以勾选信任模型，让模型审核全部已授权待审核卡片；未确认授权的卡片会自动跳过。
6. 到“结论核验”一次输入一句准备写入报告的事实性表述。系统只使用当前项目中“已确认授权 + 已批准”的证据。
7. 到“成果与缺口”查看待补证任务、结论—证据对应表和可信 Markdown 导出。

### C. 可选开启 DeepSeek 模型辅助

模型能力不是使用文字闭环的必需步骤，且不会替代本地规则或人工确认。配置环境变量并通过无项目内容的探针后，页面才会显示模型入口：

```powershell
$env:QINGJI_LLM_ENABLED = "true"
$env:QINGJI_LLM_BASE_URL = "https://api.deepseek.com"
$env:QINGJI_LLM_API_KEY = "你的 DeepSeek Key"
$env:QINGJI_LLM_MODEL = "deepseek-v4-flash"
.\.venv\Scripts\python.exe scripts\test_llm_connection.py
```

探针通过后，重启 Streamlit。在“结论核验”中可请求保守改写和补证建议；也可以明确勾选信任模型，让模型复核候选证据与结论是支持、冲突还是背景。模型关系结果会写入本条结论的关联说明，但四级结论仍由本地规则计算。在“审核证据卡 → 批量审核工具”中，只有明确勾选信任模型后，才会让模型按批次审核已授权待审核卡片并写入批准/拒绝状态。模型只接收边界再次脱敏的内容。

### D. 备份与恢复

在“项目概览 → 项目备份与恢复”中生成 ZIP 并下载。恢复时上传 ZIP、确认来源可信、填写新项目名称，再点击“校验并恢复”。恢复始终创建独立的新项目，不会覆盖原项目。

备份包可能包含原始材料，不能上传到公开仓库或发送给无关人员；`.env`、API Key、`data\qingji.db` 和 `data\raw\` 也不应提交 Git。

### 常见卡点

- **看不到模型入口**：确认环境变量是在启动 Streamlit 的同一个 PowerShell 进程中设置的，然后重启服务；批量模型审核还要求项目中有已确认授权的待审核卡片。
- **出现 `cannot import name 'render_workflow_steps'`**：说明旧的 Streamlit 进程缓存了更新前的页面模块。停止旧服务，在项目目录用项目虚拟环境重新启动，再刷新浏览器。
- **证据没有出现在结论核验**：检查材料授权是否为“已确认授权”，证据卡审核状态是否为“已批准”。
- **页面显示“暂无支持”**：这表示当前材料没有达到本地检索阈值，不等于现实世界中该说法一定为假。
- **想重新开始体验**：回到“项目概览”切换内置项目，或新建一个空项目；不要直接删除数据库文件。

### DeepSeek 联调

本项目使用 OpenAI 兼容格式连接 DeepSeek。配置好 `QINGJI_LLM_ENABLED`、
`QINGJI_LLM_BASE_URL=https://api.deepseek.com`、`QINGJI_LLM_API_KEY` 和
`QINGJI_LLM_MODEL` 后，可先运行不携带项目材料的探针：

```powershell
.\.venv\Scripts\python.exe scripts\test_llm_connection.py
```

探针只验证 Key、地址和模型是否能返回约定 JSON；通过后，再在页面中主动点击模型辅助按钮。API Key 不应写入代码、提交仓库或发送到对话中。

如需自动走完整纵向闭环（导入 → 审核 → 核验 → 补证 → 重新核验 → 导出 → 备份恢复）：

```powershell
python scripts\e2e_apptest.py
```

该脚本用 Streamlit AppTest 驱动真实页面，并在隔离的临时数据库上断言每一步结果。

如需单独运行固定检索回归集：

```powershell
python scripts\eval_retrieval.py
```

当前检查集包含 6 个固定查询：3 个直接匹配、1 个同义改写、1 个无关主题零命中和 1 个正反观点同时召回。正向目标必须进入前三名，零命中样例不得越过相关阈值；它用于防止检索规则修改后出现明显退化，不代表所有项目上的通用准确率。

用户项目还可以在“成果与缺口 → 检索评测”中下载 CSV 模板。每行填写用例名称、类别、查询、预期证据编号以及是否要求零命中。目标证据必须属于当前项目，并且已经确认授权、完成人工批准；跨项目编号会被拒绝。评测查询和结果仅保存在本地项目数据库中。

评测历史只在“用例集指纹、证据集指纹、检索版本、Top-K、相关阈值”全部一致时计算通过率变化，避免把语料或配置不同的成绩误当作性能升降。选中的运行可导出 Excel 安全的 UTF-8 CSV 或带边界声明的 Markdown；评测通过率不是事实正确率，也不是外部基准成绩。

## 项目备份与恢复

在“项目概览 → 项目备份与恢复”中点击“生成完整备份包”，再下载 ZIP。备份清单记录格式版本、各表记录数、文件大小和 SHA-256 哈希；本机数据库绝对路径不会写入可迁移项目数据。

恢复前系统会检查 ZIP 路径、成员数量、压缩前后大小、项目关系和全部哈希。恢复始终创建新项目并重新映射内部编号，不会覆盖已有同名项目；数据库重建失败会回滚，已经写入的材料文件也会清理。页面备份上限为 50 MiB，解压内容上限为 100 MiB。

备份包可能包含未经脱敏的原始材料，应按敏感调研资料妥善保管，不得提交到公开仓库或公开分享。

也可以用项目脚本一次完成单元检查、语法检查和端到端验证：

```powershell
.\scripts\test.ps1
```

如要在完全独立的临时数据目录中手动试验，可先设置：

```powershell
$env:QINGJI_DATA_DIR = "$PWD\data-local"
python -m streamlit run app.py
```

## 数据与隐私边界

- 项目材料应如实记录来源、授权和采集场景，不能把未经核验的内容当作最终事实。
- 真实录音、笔记或图片必须先取得相应的记录与使用授权；授权状态未知或被拒绝的材料不得进入结论检索和成果导出。
- 手机号、身份证号、邮箱和自定义敏感词先在本地识别。只有人工确认后的脱敏文本才适合用于后续模型处理。
- 原始材料与脱敏文本分开保存；公开仓库不提交 `data\qingji.db`、`data\raw\`、`.env` 或其他含个人信息的文件。
- 证据卡由系统提取后仍需人工审核。团队分析不能单独证明事实，单名受访者的陈述也不能自动推广为群体结论。
- 青迹给出的是“当前材料能支持到什么程度”，不是事实认证、伦理审查或法律意见。导出前仍需项目成员复核原文和来源定位。

## 当前限制（v1.1）

- 结论的四级结果仍为**本地规则判定**：识别强量词、因果表达与相反体验，并检查当前材料能支持到什么程度。云端模型可在用户确认后复核候选证据的支持/冲突/背景关系，但不直接替代四级判定。
- 大模型现在还可以在审核页经用户明确确认后批量返回证据卡的批准/拒绝建议并写入状态；模型不会接收未确认授权的卡片，启用前仍应确认服务商、费用、跨境/存储政策和项目材料授权边界。
- 证据检索默认先用本地关键词与中文字符 n-gram 限定模型复核候选集；与结论措辞差异较大的材料可能进入不了候选集，模型复核不能弥补未进入候选集的材料。
- 当前 Retrieval regression@3 仅覆盖 6 个固定项目样例，属于分类回归检查，不应表述为所有项目上的模型评测。
- 自定义评测的目标证据由用户人工指定，其质量取决于标注是否准确；评测通过率不能当作事实正确率或外部基准成绩。
- 只支持文字材料；录音转写（ASR）、图片 OCR、多智能体与知识图谱尚未接入。
- 已支持本地多项目，但仍是单用户应用，无账号系统与多人权限。
- 页面备份适用于当前文字版单项目，ZIP 最大 50 MiB；它不是持续增量备份或云端同步服务。
